# RuleTrip v0.4.0 — Matched Controls

RuleTrip v0.4 adds matched counterfactual controls so an observed guard failure must be specific enough to distinguish the planted violation from a near-identical neutral mutation.

## Evidence change

For control-configured canaries, `ALIVE` now requires:

- every clean baseline to pass;
- every violation run to reject consistently;
- every configured sensor contract to hold;
- every matched-control run to pass;
- the violation sensor to remain absent from bounded control output.

A filename-only, marker-only, flaky, truncated, timed-out, or generally rejecting response is **INCONCLUSIVE**.

## Scope

The built-in test, type-check, lint, and workflow-pin packs ship matched controls. The generic policy pack remains control-free because no scanner-independent neutral form exists.

This release does not prove semantic equivalence between violation and control, certify guard correctness, or turn RuleTrip into a process sandbox.
